# B-Music UI：安静的私人音乐空间

## 设计判断

原界面更像深色搜索工具台：大号宣传文字、荧光强调色、密集的评分与操作争夺注意力，首次进入却只有空结果。B-Music 的核心价值是发现、收藏和聆听，因此重新建立「先感受音乐，再处理参数」的层次。

参考研究：

- [Spotify 桌面布局说明](https://newsroom.spotify.com/2023-06-20/spotify-desktop-experience-redesign-your-library-now-playing-views-customize/)：媒体库、发现内容和播放上下文分工明确，常用内容容易抵达。
- [Apple Music 窗口与媒体库侧栏](https://support.apple.com/en-gb/guide/music/mus0cec331d6/mac)：媒体库导航可以按使用需求组织。

以上提供信息架构参考，不复刻品牌皮肤。暖白、鼠尾草绿、印刷感排版和原创唱片图形是 B-Music 自己的设计选择。

## 视觉系统

| 主背景 | 暖白 #FAFBF8 |

| 主色与主要操作 | 墨绿 #315E49 |

| 辅助信息 | #677064 / #737B70 |
| 栅格间距 | 20px，移动端 14–15px |
| 控件 / 卡片圆角 | 6px / 8–13px |

正文用系统无衬线字体，首页主题标题用中文衬线字体；字体不依赖外部请求。唱片、封套、山丘、磁带和月亮全部由本地 CSS 绘制，没有第三方图片依赖或新增 UI 包。

## 页面与交互

- 发现：首页主题、四个心情搜索入口、真实本地收藏。心情卡是搜索快捷入口，不伪装成已经存在的歌单。
- 搜索：回车提交；Ctrl/Cmd + K 聚焦；高级参数默认收起；加载骨架、错误提示、空结果与分页独立表达。
- 曲目：封面与紧凑列表两种视图；播放和收藏直接可达；下载、关注、复制、原视频放进更多操作。
- 收藏、关注、下载与设置：共享页面层级、表单、提示和色彩，不再像彼此独立的工具页面。
- 播放：跨路由常驻，明确展示准备状态和失败消息；队列及播放策略按需展开，支持 Escape 关闭。
- 移动端：底部五项导航、独立播放条和两列心情卡；播放设置可从队列入口访问；保留安全区间距。
- 可访问性：跳转主内容、可见键盘焦点、导航和图标控件名称、可键盘操作的队列、减弱动态效果支持。

## 业务边界

UI 与业务层分离；当前版本已移除歌曲评分并简化搜索与内核策略。首页只读取本地收藏元数据，远程搜索必须由用户明确触发。下载页表示「内核已准备、可下载」，不推断设备中已经存在文件，也不保证无损音质。

修复了界面中的接线问题：播放准备指向现有 /api/tracks/prepare；播放器封面使用 /api/image-proxy；收藏使用返回的 isFavorited 而非不存在的 GET；关注表单提交现有 API 支持的 biliMid / homepageUrl。

## 验证

- npm run typecheck
- npm test（27 项集成检查 + 17 项单元测试）
- npm run build
- 浏览器人工核对：桌面首页、真实本地搜索、封面／列表切换、手机首页和播放队列／设置入口。

真实内核音频提取、播放和设备下载未在本次 UI 验证中端到端执行。没有向收藏或关注列表插入演示数据。
