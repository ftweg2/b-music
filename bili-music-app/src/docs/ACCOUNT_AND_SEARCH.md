# 账号、发现与搜索分工

## 本地音乐库和 B 站账号

默认按内核已验证的 Bilibili 账号区分收藏、关注、歌单、曲目和播放区间。同一服务当前同一账号的网页与手机 API 共用这些记录；换号切换分区，切回可恢复。
当前仍是一套服务同一时刻使用一个 Bilibili 登录，不是每设备各自登录的多用户鉴权服务。旧本地库一次性归入首次确认的登录账号；未登录使用单独 guest 分区。APP_LIBRARY_MODE=local 可显式保留本地模式，客户端 cookie 不决定身份。
设置页提供扫码登录、退出登录和更换账号。退出或更换前会明确确认。

退出只删除当前 owner 对应的内核浏览器登录资料，不触碰 App SQLite、内核数据库、音频 artifacts 或其他 profile。
内核先关闭当前 profile 的待扫码任务，再取得独占锁。音频处理／搜索仍占用锁时返回 409，不强行中断。
更换账号按「成功退出旧登录 → 创建新二维码」执行。新二维码创建失败时明确显示旧账号已经退出，用户可重新发起扫码；不会偷偷恢复旧登录。

二维码在登录成功、过期或取消后关闭；状态查询使用串行、可取消、有限时长的轮询。
登录状态变化清理当前展示的搜索会话、停止旧播放器和关闭区间草稿；收藏、关注、歌单与区间不删除，播放队列在设备内按账号分别保存。

登录、退出与换号的调用顺序、确认参数和允许来源统一见 [API 调用文档](API_USAGE.md)。客户端只调用 App API；浏览器 Cookie 和存储文件始终留在内核边界内，不返回客户端。

## 搜索与分页

新搜索默认 provider=auto：已登录优先内核，未登录使用普通接口。自动选择只发生在新搜索第一页，不发生在翻页中。
每次成功结果保留完整查询条件、实际来源、实际页大小与登录会话上下文，并返回 searchId。翻页始终沿用这些条件，已访问页复用快照。跨页去重和跳页细则见 [PAGINATION.md](PAGINATION.md)。

在线请求失败返回错误，不再用同一页码去查询本地。失败后仍显示最近一次成功的结果，并注明「第 N 页未加载，仍显示第 M 页」。
用户可重试失败页，或明确点击「改查本地（从第一页开始）」。空结果页依然保留上一页入口。
登录态变化后旧 sessionKey 失效，服务器返回 SEARCH_SESSION_CHANGED，客户端要求重新从第一页搜索。

search_query_logs 增加 provider、page、error_message，保存经过脱敏的诊断信息，不记录 Cookie 或登录凭证。
旧数据保留，旧版混合来源的客户端搜索缓存不再使用。

## 发现与搜索

发现页只展示音乐库快捷入口、已有歌单、收藏和心情探索，不再包含完整搜索表单或结果列表。
心情与主题入口通过带一次性 run 标记的链接跳到 /search，代表用户明确发起的搜索。
结果 URL 会移除 run 标记；刷新、普通返回与书签恢复不会自动重复远程搜索。
旧版 /?q=... 书签会跳到 /search 并保留查询条件。

## 验证边界

当前验收范围、隔离真实浏览器测试和正式服务有限联调证据见 [手机 API 验收记录](MOBILE_API_ACCEPTANCE.md)。退出、取消和换号测试只使用隔离账号，不退出真实用户的 Bilibili 账号。
