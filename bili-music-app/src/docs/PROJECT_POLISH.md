# 核心链路整理记录


> 后续账号与分页调整已禁止自动回退到本地，发现页也不再承载搜索结果。当前行为以 [账号与搜索说明](ACCOUNT_AND_SEARCH.md) 为准；以下保留本轮历史记录。
## 本轮完成

### 搜索与评分

- 删除歌曲评分、创作者权重、推荐理由组件、评分算法及对应旧测试。
- 公共对象由 CandidateWithScore 更名为 CandidateItem，不再返回任何歌曲分数或权重。
- 在线搜索只请求选定来源的一页，保持来源顺序，不混入旧缓存、不追加关注 UP 搜索。
- 本地搜索按多个词共同匹配，转义 SQL 通配符；稳定按最近发现时间和 ID 排序。
- 在线成功但无结果，不伪装成缓存命中；远程失败才回退本地，并正确报告来源与错误。
- 实际页面大小与来源能力一致；使用上游页数或本地哨兵记录判断下一页。
- 输入 BV/视频链接不会触发通用搜索或自动提取。仅本地模式不会创建不存在的视频记录。
- 跳过单条坏结果，规范化视频链接，容忍异常时间戳，不让一条坏数据毁掉一页结果。

### 保存与一致性

- 简略元数据不会覆盖已经保存的封面、时长、标签和创作者信息。
- 重复收藏保留已有备注和心情；显式传 null 可以清空对应字段。
- 收藏状态同步到其他曲目卡、首页和本次搜索缓存；移除收藏后刷新服务器页面。
- 关注是明确的创作者书签；读取关注列表不再隐式联网解析名称。
- 关注链接只接受有效的 Bilibili 空间地址，不再把备注中的数字误认成 UID。
- 播放队列先恢复、验证、去重和限制长度，再写回，避免初始化覆盖保存状态。
- 不跨 owner 恢复其他人的收藏快照；并发读取同一准备任务只发一次内核状态请求。

### 播放与内核

- 删除未实现的预热入口和闲置状态。
- 播放准备、下载准备统一使用可取消的串行轮询；请求超时、失败、过期或五分钟总时限后停止。
- 切歌、清空队列、组件卸载时取消旧的前端请求，旧响应不能覆盖当前曲目。
- 播放在媒体就绪事件后启动，不再靠固定 100ms 延时猜测。
- 下载准备去重并限制为一个；明确区分「交给浏览器下载」与「下载完成」。
- 内核自动策略不再打分，严格按显式顺序执行；未列出的实验策略不会偷偷追加。
- 内核搜索覆盖浏览器启动和请求的整体超时，并确保超时后释放 profile 锁。
- 上游业务错误不再返回空成功；坏数据、重复 BV、异常日期和时长有针对性的防护。
- 音视频识别、资源访问边界、Range 代理及音轨校验保持不变。

### 界面

- 删除曲目菜单、详情、关注页的评分和加权说明。
- 详情页回到原来的查询、搜索来源与页码。
- 更多操作菜单避让播放器；长查询标题、请求取消和缓存恢复做了相应整理。

## 数据兼容

没有清空或重建用户的收藏、关注、曲目数据库；没有插入演示收藏或音频。
新数据库不创建评分列。老数据库中可能仍有不再读取、更新或返回的评分列，保留它们是为了无损兼容，而不是保留评分功能。
删除的算法和组件是源代码文件，可通过 Git 历史恢复；这次没有修改 Git 提交或已有未提交的无关改动。

## 验证

- App：21 项集成检查 + 40 项单元测试。
- Kernel：81 项测试，包括新增超时、锁释放、错误响应、显式策略顺序等回归。
- TypeScript 类型检查、Next.js 生产构建。
- Docker Compose 配置解析。
- 浏览器：实际本地多词搜索、菜单、详情返回、评分移除与 UI 状态。

内核测试使用隔离的临时数据目录及模拟上游；真实 Bilibili 提取、连续音频播放、设备下载尚未在本轮做完整验收。
没有重启或重新部署用户现有内核容器。内核源码变更需在实际部署环境重新构建容器后生效。
取消前端等待不会自动取消已提交的内核作业，以免中断被下载或其他客户端复用的任务。
