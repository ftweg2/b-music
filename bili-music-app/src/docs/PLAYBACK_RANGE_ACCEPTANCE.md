# 账号同步与播放区间验收

目标：按 Bilibili 账号和 BV 保存开始/结束时间，网页和手机 API 共用服务器设置；每次点选歌曲从设置的起点开始，到显式终点停止；播放器提供明显的关注 UP 按钮。已有库需要安全迁移，不能用客户端自报 UID 选择别人的数据。

## 验收门槛

- [x] 持久化：同账号同 BV 读写一致，换号隔离，切回可恢复，重启仍在。
- [x] 并发：版本冲突和重发明确处理，不发生跨账号误写，非法区间被拒绝。
- [x] 播放：首次播放、重新点歌、暂停恢复、拖动、上一首、自然结束、指定结束、刷新及队列均遵守区间。
- [x] 手机 API：独立 HTTP 客户端写、网页读，网页写、HTTP 客户端读；契约和调用指南完整。
- [x] 关注入口：桌面/手机播放栏可见，当前 UP 正确；保存与其他页面同步，换号不串状态。
- [x] 迁移：原库保留且不会分配给多个账号；内核凭据和音频仍只在内核。
- [x] 回归：类型、单元/集成、隔离 HTTP、浏览器交互及部署健康检查通过。

只在各项有对应证据后完成目标。测试不退出真实用户账号，不为测试删除真实曲目或播放设置。

## 接入和边界

当前 API revision 为 1.2.0，29 条路径、40 个方法操作；`GET/PATCH /api/playback-ranges/{bvid}` 和所有 Track 响应均提供账号区间。完整调用顺序、请求字段、版本冲突和手机播放器行为见 [API 使用文档](API_USAGE.md)。

同步指连接同一套服务、使用其当前已验证 Bilibili 账号的客户端共用数据；当前是一套服务一个活动登录，不宣称每设备独立多用户认证。原始音频保持完整，内核已有身份与媒体接口满足本次需要，没有新增转码或改写音频；手机客户端需要按照返回的 playbackRange 控制播放，不能假定任意播放器打开裸 streamUrl 就会自动裁剪。

测试使用隔离的真实 Chrome/ffmpeg 与合成音频，不把假二维码用于真实登录。生产只核对迁移、登录、元数据和健康，不替用户选择真实歌曲的起止点。所有通过结果限于记录的验收范围，不承诺未来上游或任意输入永远无故障。
